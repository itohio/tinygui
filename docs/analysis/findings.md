# Findings

Defects and risks found while documenting `b140156` (F-01…F-21) and while building the Tufty 2040 demo (F-22…F-30), in ID order. Each has evidence: a source line, a measurement in [[baseline]], or a probe. Scope says where the defect lives (library / example / tool / driver / docs). Tickets: F-01 → [[t-0001-m5stickc-examples-build]]; the rest are input to the TG-1b ranking in [[analysis]].

| ID | Severity | Scope | Finding | Effect for an app author | Evidence |
|---|---|---|---|---|---|
| F-01 | blocker | example | Neither example builds for the M5StickC with TinyGo 0.43 / drivers v0.31.0: `machine.Serialer` is undefined on classic ESP32, then `st7735.Device` does not satisfy `ui.Displayer` | the M5StickC demos don't compile; any app importing `ui` fails on classic ESP32 | [[t-0001-m5stickc-examples-build]], [[baseline]] |
| F-02 | high | example | Example geometry targets a 240×135 panel (`examples/choice/main.go:22-23`) but the board config sets up an 80×160 ST7735 rotated to 160×80 (`examples/m5stick/cfg_m5stickc.go:55-62`). 240×135 is the M5StickC **Plus** (ST7789). Most of the UI would fall off-screen on a StickC | on a StickC most of the demo UI is off-screen | source; needs the owner's device to settle ([[analysis#Known unknowns]]) |
| F-03 | high | library | Stateful layouts carry state across frames: `Grid`, `HFlow`, `VFlow` initialise `startX`/`rowHeight` once per closure (`layout/layout.go:36-48`, `:73-85`, `:114-126`). Second frame places wrapped rows at the previous frame's last row height. A container with a zero dimension also runs the same closure in `determineSize` (`container/base.go:86-88`, `:111-119`), so measurement state leaks into the first frame too #verify (probe used fixed sizes), and one `Strategy` value shared by two containers shares state | Grid/HFlow/VFlow rows shift on the second frame | probe `TestGridStableAcrossFrames`: 4th child at `(0,10)` on frame 1, `(0,30)` on frame 2 ([[baseline#Host probes]]) |
| F-04 | high | library | Layout wraps after drawing: the child that overflows the row is drawn first, then the cursor wraps (`layout/layout.go:58-67`); with 3×10 px children in a 25 px grid the third is drawn at x=20 and spills 5 px outside | the last item of a row spills past the container edge | same probe, child 3 at `(20,0)` |
| F-05 | high | library + driver | Text is drawn pixel by pixel. `tinyfont` glyph drawing calls `SetPixel` per set bit (`tinyfont@v0.6.0/concrete.go:40`); on the ST7735 `SetPixel` is `FillRectangle(x,y,1,1)`, i.e. a window set + SPI transfer per pixel (`examples/m5stick/st7735/st7735.go:205-211`; upstream identical pattern) | text is the slowest thing you draw on SPI panels | source; frame-time impact to measure on hardware |
| F-06 | high | example + library | Full-screen clear + full redraw every frame on an unbuffered panel (`examples/choice/main.go:185-189`, `Display()` is a no-op) → visible flicker and wasted SPI bandwidth; no dirty tracking anywhere | visible flicker on unbuffered panels; wasted bus time | source; visual check pending hardware |
| F-07 | medium | library | Heap allocations on the steady-state render path: `ContextImpl.Clone` returns `&ret` (`context.go:79`), `offsetContext.Clone` (`container/scroll.go:156`), `InteractiveLabel` formats with `fmt.Sprintf` + concatenation each draw (`widget/interactive_label.go:37`, `:149-155`); per input: `ScrollChoice.measure` (`container/choice.go:166`), navigator `Path` (`navigator.go:168`), `Label.SetText` closure (`widget/label.go:52`) | garbage every frame → GC pauses in the UI loop | TinyGo `-print-allocs`: 2 per-frame + 3 per-input sites in the choice demo; host: 14 allocs/frame for a 3-widget scene, 6 per selected `InteractiveLabel.Draw` ([[baseline#Allocations]]) |
| F-08 | medium, **fixed (uncommitted)** | library | `Icon` decodes its PNG on every `Draw` (`widget/icon.go:13-18` → `drawing.go:58-76`); the decoder's callback buffer is a package global shared by all icons (`drawing.go:52`), and the source carries a note about memory corruption with an older TinyGo (`drawing.go:54-56`) | icons cost a PNG decode per frame (13 KB garbage each, host-measured); now decoded once per image change | source; fix: `widget.Icon` caches an RGB565 buffer via new `ui.DecodePng`, test `TestIconDrawsDecodedPixels` |
| F-09 | medium | example + font lib | Assets and fonts live in RAM: example icons are `var X = []uint16{…}` (`examples/choice/icons/*.go`) and land in `.data`, 10 112 B of RAM; `tinyfont` glyph tables add 5 845 B. Together 72 % of the choice demo's 22 252 B static RAM | fonts and images eat RAM, not flash | `-size full` ([[baseline#Size]]) |
| F-10 | medium | library + example | Missing glyphs: `InteractiveLabel` draws `▲`/`▼` (`widget/interactive_label.go:152`) and the gauge example uses `–` (U+2013) (`examples/gauge/main.go:158`); the default `TomThumb` font stops at U+00EB, so these render as nothing | some characters render as nothing | `tinyfont@v0.6.0/tomthumb.go`, last glyph rune 235 |
| F-11 | medium | library | `Log.Append` re-allocates the whole slice on every append once at capacity (`widget/multiline.go:201-209`) | each log line at capacity reallocates the history | host probe: 2 allocs per append at capacity 16 |
| F-12 | medium | library + example | `Bitmap16` silently draws nothing when the slice is shorter than `w*h` (`widget/bitmap.go:52-55`); the choice example builds a 40×40 bitmap from the 16×16 thermometer (`examples/choice/main.go:141`, `examples/choice/icons/thermometer.go:4-5`), so that choice is blank | a wrongly sized bitmap is silently blank | source |
| F-13 | medium | library | No clipping: widgets draw at absolute positions with no bounds; a widget wider than its container, or a scrolled child partly out of the viewport, paints outside (`container/scroll.go:121-142` only skips fully invisible children) | widgets can paint over neighbours and chrome | source |
| F-14 | low | library | `SerialReader` + `CommandStreamMux` busy-poll: 1-byte reads, `runtime.Gosched()` per byte, 0-byte reads when idle (`mux.go:22`, `:30-33`; `serial_reader.go:18-31`) | the serial console burns CPU while idle | source |
| F-15 | low | library | `ui.go` and `serial_reader.go` gate on hand-written chip lists that disagree (`xiao`) and miss families such as `esp32s3`; TinyGo provides `serial.usb`/`serial.uart` tags | some boards (e.g. ESP32-S3) silently lose `PeekButton` and the serial reader | [[topology#Build tags and per-target files]] |
| F-16 | low | example | `examples/choice/icons/generate.go` runs `go run ../media …`; `examples/choice/media` does not exist, so `go generate` fails; the arrays were evidently produced by `cmd/png2bin` (same output format) | `go generate` for the choice icons fails | `ls examples/choice` |
| F-17 | low | library + example | Dead code: `examples/m5stick/{i2c,st7735,mlx90614}` are not imported; `animation` is not imported; `ui.Container`, `Padder`, `Marginer`, `LineDisplayer` have no users | dead code to read past | [[topology]] |
| F-18 | low | tool | `png2bin` accepts `.jpg/.jpeg` then fails in `png.Decode`; output package name hard-coded to `icons` (`cmd/png2bin/png2bin.go:41-43`, `:56`, `:69`) | JPEG input fails; output package fixed to `icons` | source |
| F-19 | low | docs | Docs drift in the former `DESIGN.md` | the old design doc misleads | [[design-intent#Drift from the code]] |
| F-20 | high | library | Overflowing content is dropped without any signal: `VList`/`HList` return false once the cursor leaves the context and `Base.Draw` stops drawing the remaining children (`layout/layout.go:20`, `:30`, `container/base.go:149-151`). In the gauge demo the status and summary labels are never drawn (248 px of content on a 135 px screen) | children past the bottom edge vanish silently | probe `TestGaugeExampleVerticalBudget` ([[baseline#Host probes]]), [[example-gauge]] |
| F-21 | medium | driver | The ST7735 driver allocates four slices per `setWindow` (`examples/m5stick/st7735/st7735.go:222-225`; upstream v0.31.0 `st7735/st7735.go:255-258` identical), and every rectangle, bitmap and pixel goes through it; text therefore costs 4 allocations per lit pixel (with F-05) | 4 allocations per lit text pixel on ST7735 | `-print-allocs` on the vendored-driver build ([[baseline#Allocations]]); upstream by source reading |
| F-22 | high, **fixed (uncommitted)** | library | `Scroll` laid children out in a viewport-sized context, so the layout stopped at the viewport edge and rows scrolled into view were never drawn (`container/scroll.go` `drawVisible`); fix: lay out in a content-sized context, test visibility against the viewport | scrolled-in list rows were blank (fixed) | regression test `TestScrollDrawsContentBeyondViewport` failed before (`row 4: should have 1 item(s), but has 0`), passes after; Tufty list page screenshot [[example-tufty2040]] |
| F-23 | medium | library | `ScrollChoice` change callbacks (`WithScrollChoiceChange`) fire only for selector-driven moves; focus moved by the `Navigator` (`SetIndex` via `Base`) does not call them (`container/choice.go:62-67`, `:115-118`) | list change callback misses button navigation | Tufty list page: detail panel had to read `list.Index()` |
| F-24 | medium | library | The container idle timer counts only `Interact` calls (`container/base.go:160`); navigator moves don't reset it, so focus driven purely by the `Navigator` is cleared after `Timeout` even while the user is pressing buttons | focus clears after 10 s although you are pressing buttons | Tufty app sends a no-op `Interact(ui.USER)` on every press as a workaround (`examples/tufty2040/app/app.go`, `Press`) |
| F-25 | low | library | `InteractiveMultiGauge` shows no marker for the segment being edited (`widget/interactive_gauge.go:198-412`; `MultiGauge.Draw` has no active index) | you can't see which segment you are editing | Tufty screenshot `04-gauges-edit-mix` |
| F-26 | medium | library | `NewInteractiveLabel` installs a `fmt.Sprintf` default formatter (`widget/interactive_label.go:37`), linking `fmt` + `strconv` (≈ 34.5 KB flash) into every app that uses it, even when the app passes `WithFormatter` | +34 KB flash even if you never use `fmt` | `tinygo build -target=tufty2040 -size full`; the demo app imports no `fmt` |
| F-27 | medium | library + driver lib | Linking `widget.Icon` pulls the drivers' PNG decoder: 13.6 KB flash and a 34 856 B inflate window in `.bss` | +34 KB RAM as soon as you use `Icon` | Tufty `-size full`: `drivers/image/internal/compress/flate` 34 856 B bss |
| F-28 | medium | library | Activation sticks to the wrong child: `Navigator.Enter` into a sub-container activates its first child (`navigator.go:138`), and `Base.SetIndex` moves focus without deactivating the old child or activating the new one (`container/base.go:174-192`), so `OnActivate` state stays on a row the user left | rows keep showing "editing" after you move on | Tufty badge dump of the List page (Channel 01 still framed as editing while Channel 11 is focused); app hides it by drawing the edit state only on the focused row |
| F-29 | medium | font lib | `tinyfont.WriteLine` allocates on every call (a `[]color.RGBA{c}` and a rotated-display wrapper, `tinyfont@v0.6.0/tinyfont.go:56-64`); every `Label` draw creates garbage | ≈ 700 allocations per frame, ≈ 12 GC runs per second on the showcase | host pprof: 97.6 % of frame allocations in `WriteLineColorsRotated`; badge `stats` counters |
| F-30 | high | example | A full 320×240 RGB565 framebuffer (153.6 KB) left ≈ 50 KB of heap; the showcase ran out of memory (`fatal error: out of memory` on the serial console) after a few page changes | the badge froze; fixed in the example by drawing in two 120-row bands (76.8 KB) | serial capture 2026-11-12; banded build stable over 28+ page changes, `heap_alloc` 83–107 KB of 117 KB |
